## 3. 定制能力：去酱 / 少酱 / 加肉饼

### 3.1 数据结构真相

`query-meal-detail` 的 `modification.items[]` 是**减法结构**：

```json
{"maxValues":2,"minValues":0,"values":[
  {"code":"100136","price":0,"name":"麦香鸡酱","maxQuantity":1,"minQuantity":0,
   "selectedQuantity":1,"selectedKey":"0-1","unselectedKey":"0-0"},
  {"code":"120512","price":0,"name":"切块生菜","maxQuantity":1,"minQuantity":0,
   "selectedQuantity":1,"selectedKey":"0-1","unselectedKey":"0-0"}
]}
```

关键含义：
- `maxQuantity` 恒为 `1` → **只能留或去，没有 0.5 份**，所以"少酱"无法表达。
- `price` 对餐品去料恒为 `0` → 去酱不改价。
- 没有 `+1 片肉` 这类 `values`。

### 3.2 抽检结果

| 餐品 | code | supportModify | 可去项 | 少酱 | 加1/2块肉饼 |
|---|---|---|---|---|---|
| 麦辣鸡腿汉堡 | `1440` | true | 麦香鸡酱 `100136`、切块生菜 `120512` | ✗ | ✗ |
| 板烧鸡腿堡 | `1406` | true | 烤味酱 `102201`、切块生菜 `120512` | ✗ | ✗ |
| 芝士安格斯厚牛堡 | `511782` | true | 醇香芝士风味酱 `100201`、高达干酪片 `102215`、番茄片 `102225`、黄油 `120160` | ✗ | ✗ |
| 培根安格斯厚牛堡 | `511781` | true | 吉士 `100141`、烤牛肉风味酱 `100179`、切块生菜 `120512`、培根 `103386`、黄油 `120160` | ✗ | ✗ |
| 猪柳蛋麦满分（早餐） | `5022` | true | 吉士 `100141` | ✗ | ✗ |

**对照证据（"+1"确实存在，但只在饮品）**
- `507411` 麦咖啡美式：`8008`「加」`price:500`（+¥5.00），`unselectedKey` 不适用，`selectedKey` `0-1`
- `515946` 浓浓黑巧：`120146`「换燕麦奶」`price:200`（+¥2.00）

结论：接口**有能力**表达加价加料，但**餐品侧没有肉饼加料 SKU**。这不是我们没找到，是菜单没开。

### 3.3 套餐结构（与三餐规划相关）

`9900005456` 麦辣鸡腿汉堡三件套 = `rounds[]` 三选配轮：
- round 1 主食：`1440`，`supportModify=true`，可沿用单品特调
- round 2 小食：中薯条 `4810`(默认,+0) / 心形薯饼+酱 `521983`(+¥1) / 扭扭薯 `521901`(+¥1.5) / 大薯条 `4820`(+¥2.5) / 小杯玉米杯 `4437`(-¥0.5) / 大杯玉米杯 `4438`(+¥2.5)
- round 3 饮料：可乐中杯 `3050`(默认,+0) / 多汁柠柠 `521817`(+¥1) / 奶昔 `521588`(+¥8) / 纯牛奶 `3755`(+¥0.5) / 美式 `507411`(+¥9) / 锡兰红茶 `3505`(+¥1.5) …

**这是 MVP 的换配基础**：套餐换小食/饮料有明确 `diffPrice`，可做"低卡替换"（中薯 → 小玉米杯 −¥0.5，减 68 kcal）。

## 5. 营养数据核对

### 5.1 官方数据（可用）

`list-nutrition-foods` 返回 160 行 / 158 个唯一餐品，字段：

`productName, nutritionDescription, energyKj, energyKcal, protein, fat, carbohydrate, sodium, calcium`

- 计量基准：**单份**
- 接口 payload **不带单位字符串**，单位由字段名承载（kJ / kcal / g / g / g / mg / mg）
- 官方口径（麦当劳中国官网同页说明）：数据由供应商信息 + 全球营养程序手册标准，经国家认可实验室测定；**更新时间 2025 年 4 月**
- 交叉核对：官网「麦辣鸡腿汉堡」页 = MCP 返回，完全一致（2029 kJ / 24 g / 24 g / 42 g / 1208 mg / 154 mg）→ **MCP 数据与官网同源，可信**

### 5.2 覆盖缺口

营养表是**成品级**的。搜索 158 个名称，**没有任何**酱料、肉饼、芝士片、生菜、面包等**单一成分**条目。
→ 因此：任何"去酱/加料"后的营养，都**无法**从官方表直接得到。

## 6. 可复算估算案例：麦辣鸡腿堡「去麦香鸡酱」

### 6.1 输入

| 项 | 值 | 类别 |
|---|---|---|
| 标准版 麦辣鸡腿堡：能量 | 2029 kJ / 485 kcal | **官方**（S1） |
| 蛋白质 / 脂肪 / 碳水 | 24 / 24 / 42 g | **官方**（S1） |
| 钠 / 钙 | 1208 / 154 mg | **官方**（S1） |
| 麦香鸡酱 每份：能量 | 68 kcal | **估算**（S2） |
| 蛋白质 / 脂肪 / 碳水 | 0.2 / 6.5 / 2.3 g | **估算**（S2） |
| 麦香鸡酱 钠 / 钙 | 缺项 | **数据不足** |

内部一致性校验：0.2×4 + 6.5×9 + 2.3×4 = 68.5 kcal ≈ 68 ✓（S2 自洽，但仍属二手）

### 6.2 计算

```
去酱版 = 标准版 − 麦香鸡酱贡献
能量   = 2029 kJ − 284.5 kJ = 1744.5 → 1745 kJ   （68 kcal × 4.184 = 284.5 kJ）
       = 485 kcal − 68 kcal = 417 kcal
蛋白质 = 24 − 0.2 = 23.8 g
脂肪   = 24 − 6.5 = 17.5 g
碳水   = 42 − 2.3 = 39.7 g
钠     = 1208 mg − 缺项  → 只能给"< 1208 mg"，具体值缺项
钙     = 154 mg − 缺项   → 只能给"< 154 mg"，具体值缺项
```

### 6.3 结果

| 指标 | 标准版（官方） | 去酱版（**估算**，含缺项） |
|---|---|---|
| 能量 | 2029 kJ / 485 kcal | **1745 kJ / 417 kcal** |
| 蛋白质 | 24 g | **23.8 g** |
| 脂肪 | 24 g | **17.5 g** |
| 碳水 | 42 g | **39.7 g** |
| 钠 | 1208 mg | **< 1208 mg（缺项，不给值）** |
| 钙 | 154 mg | **< 154 mg（缺项，不给值）** |

**因为含 S2 估算项，整行必须标 EST（估算）。**

### 6.4 场景假设（待用户确认，不是门店官方用量）

| 假设 | 值 | 依据 | 状态 |
|---|---|---|---|
| 酱料份量 | 未给出克重 | S2 只给"每份"，未标克重 | **待确认** |
| 敏感性上界份量 | 15 g/份 | 常见调味酱单份用量惯例，非官方 | **待确认** |

**敏感性区间（有依据的上下界）**
若酱料按 15 g、S3 蛋黄酱（2912 kJ/100g、脂肪 76.5 g/100g）：

```
能量上限 = 2912 × 0.15 = 436.8 kJ ≈ 437 kJ（≈104 kcal）
脂肪上限 = 76.5 × 0.15 = 11.5 g
→ 去酱版能量区间 1592–1745 kJ（381–417 kcal），脂肪区间 12.5–17.5 g
```

区间成立理由：下界来自 S2 每份值，上界来自 S3 标签 × 份量假设。**份量假设未确认前，只展示区间边界，不给单一"精确值"。**

### 6.5 加肉饼：为什么算不出来

## 9. 六个必答问题

### A. 哪些餐品支持少酱、去酱和加肉？

- **去酱：支持**。抽检 5 款中 5 款都有「去酱/去配料」开关（麦辣鸡腿堡去麦香鸡酱、板烧去烤味酱、安格斯去醇香芝士风味酱/烤牛肉风味酱、猪柳蛋麦满分去吉士）。
- **少酱：不支持**。`maxQuantity=1` 是二值模型，没有 0.5 份。
- **加肉饼：不支持**。餐品侧无任何肉饼加料 SKU；只有饮品有"加浓缩 +¥5 / 换燕麦奶 +¥2"这类加料。
- **可去项因品而异**（生菜、芝士、培根、黄油、番茄都能单独去掉），这反而是健身场景的**可用杠杆**。

### B. 定制后的价格和营养分别能做到什么程度？

| 维度 | 能做到 | 做不到 |
|---|---|---|
| 价格 | 标准版/套餐/换配的**分**级准确；去料 0 价差已验证 | 加料加价不生效（+¥5/+¥2 试算未体现）；真实结算需门店确认 |
| 营养 | 标准版**官方单份**精确值；去酱版可做**区间估算**（能量/蛋白/脂肪/碳水） | 钠、钙**必然缺项**；加肉饼**完全不可算** |

### C. 是否能分别查询早餐、午餐、晚餐菜单？

**能。** `reservationDate` 传 `2026-10-19 08:00` 返回早餐菜单（麦满分/粥/厚松饼堡），传 `12:00` 返回正餐菜单，两者分类集互斥。不传则返回**当前时刻**菜单。
限制：午餐与夜市菜单结构相同，只能靠时间点区分；跨日边界与预约下单链路未验证。

### D. 哪些成分能有依据地估算？

| 成分 | 能否估算 | 依据 |
|---|---|---|
| 麦香鸡酱（去酱） | **能**，区间 | S2 每份 68 kcal（二手）+ S3 100g 标签 × 15g 假设 |
| 切块生菜（去生菜） | **能**，但影响极小 | 需另找来源；本轮未取，标"待补" |
| 吉士/培根/黄油（去料） | **能**，需补充来源 | 台湾官方有单片值（S2 页），属二手 |
| 牛肉饼（加肉饼） | **不能** | 无可下单 SKU + 无中国大陆官方单份重量 |
| 酱料钠/钙 | **不能** | 所有来源均无单份钠钙 |

**计算案例（见 §6）**：
```
去酱版 = 2029 kJ − 284.5 kJ = 1745 kJ（417 kcal）
蛋白质 24 − 0.2 = 23.8 g ｜ 脂肪 24 − 6.5 = 17.5 g ｜ 碳水 42 − 2.3 = 39.7 g
钠 < 1208 mg（缺项）｜ 钙 < 154 mg（缺项）
区间上界（15 g 假设）：1592 kJ / 381 kcal，脂肪 12.5 g
```
**缺项**：酱料钠、酱料钙、酱料实际克重。

### E. 「全天三餐规划—记录实际摄入—调整剩余餐次」的最小版本

```
① 建档
   身高/体重/年龄/性别/活动量 → BMR(Mifflin-St Jeor) × 系数 = TDEE
   目标：热量 = TDEE ± 调整量；蛋白 = 1.6 g/kg；脂肪 = 25–30% kcal；碳水 = 余量
   预算上限（元/天）＋ 口味偏好 ＋ 门店 storeCode

② 取菜单（一次取三餐）
   query-meals(storeCode, orderType=1, beType=1, reservationDate=当日 08:00)
   query-meals(... reservationDate=当日 12:00)
   query-meals(... reservationDate=当日 18:00)
   → 三份 SKU 池，按 code 去重

③ 建索引
   list-nutrition-foods() → name → {kJ, kcal, P, F, C, Na, Ca}
   query-meal-detail(code) → 可去项集合 + 套餐 rounds/diffPrice
   名称对齐：接口 nutrition 名与菜单名不完全一致 → 用归一化（去括号/去空格）＋人工别名表兜底

④ 求解（每餐 1 主 + 1 配，全天 3 餐）
   目标函数：最小化 |Σ热量 − 目标| + λ1·|Σ蛋白 − 目标| + λ2·超预算
   约束：蛋白 ≥ 目标×0.9；脂肪 ≤ 目标×1.1；总价 ≤ 预算；钠 ≤ 上限（有值才算）
   规模小：3 餐 × (主 8–15 选 × 配 5–8 选) → 暴力枚举即可，无需 MILP

⑤ 展示
   每餐卡：SKU 名 + 定制标签（去酱）+ 价格（calculate-price 试算）+ 营养（官方 or EST）
   全天：Σ能量/蛋白/脂肪/碳水 与目标差额；钠显示"不完整"若有 EST 项

⑥ 记录
   用户点"我吃了这餐" → 写入 {code, 定制, 时间}
   从当日剩余目标里扣除（**按实际吃的版本扣**，含 EST 项则整体标 EST）

⑦ 重排
   剩余餐次重新跑 ④，约束改为"剩余目标"，已吃餐次锁定不再变
```

关键设计约束（来自本轮验证）：
- **不做加肉饼**、**不做少酱**，UI 层直接不出现，避免用户预期落空。
- 价格只按标准版展示，**不承诺定制加价**。
- 任何 EST 项 → 该餐与全天合计都打 `估算` 角标；缺项显示 `—`，**绝不显示 0**。

### F. 首版输入、输出、计算规则 + 暂缓

**输入**
| 字段 | 必填 | 说明 |
|---|---|---|
| 身高/体重/年龄/性别 | ✓ | 算 BMR |
| 活动系数 | ✓ | 1.2 / 1.375 / 1.55 / 1.725 |
| 目标（减脂/维持/增肌） | ✓ | 决定热量调整量 |
| 蛋白目标 g/kg | 可选 | 默认 1.6 |
| 日预算（元） | ✓ | 硬约束 |
| 门店 storeCode | ✓ | 由城市+地标检索选定 |
| 三餐时间点 | 可选 | 默认 08:00 / 12:00 / 18:00 |
| 忌口/偏好 | 可选 | 排除 SKU |

**输出**
- 三餐方案（每餐：SKU、定制、价格、营养、EST 标记）
- 全天合计 vs 目标差额（能量/蛋白/脂肪/碳水；钠单列并标完整性）
- 总价 vs 预算
- 每餐可替换项（含 diffPrice 与热量差）

**计算规则**
1. 营养优先取官方单份值；同一 SKU 只允许一个来源。
2. 定制后营养 = 官方值 − Σ(可去项 × 有来源的单份值)，**每项必须带来源 ID**。
3. 缺项 → `null`，合计时跳过并标记"不完整"，禁止按 0 处理。
4. 含任一定制估算项 → 该餐 + 全天合计标 EST。
5. 价格：`calculate-price` 的 `price`(分) ÷ 100；定制不加价。
6. 钠：标准版可展示；去酱后只给 `<标准版值`。

**首版暂缓**
| 项 | 原因 |
|---|---|
| 加肉饼 / 少酱 | 接口无选项 |
| 定制加价展示 | 试算不生效 |
| 钠/钙精确合计 | 成分级钠钙数据全缺 |
| 外送（麦乐送） | 需地址，本轮不做；且涉及用户隐私 |
| 预约下单 / 真实支付 | 超出只读验证范围 |
| 积分、券、抽奖 | 与健身规划无关，且有副作用 |
| 500 大卡套餐自动推荐 | 数据可用，但需先验证 SKU 与目标人群匹配度 |
