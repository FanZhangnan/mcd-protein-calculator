# 13 · 数据显示修复

> 门店：珠海屏湾一路 `1440054`；数据来源：`/api/refresh` 实时 + 离线 fixture 对照。
> 全部验收使用隔离数据目录 `/tmp/mai-a-*`，未写入真实 `data/`；未下单、未领券、未动积分、未建地址、未输出 Token。
> 本轮**只改数据显示**，不改颜色、字体、布局——视觉全部留给下一阶段（14）。

## 0. 结论

1. **价格不一致不是计算 bug，是离线 fixture 数据**。用户看到的「双层深海鳕鱼堡 24.00 / 麦香鸡 17.00」来自离线样例 `menu_lunch_1215.json`（`9900003586 = 24`、`1450 = 17`），实时接口返回 25.0 / 16.5。按补充说明**不改价格数据本身**，改为在页头做**数据来源徽标**，让用户一眼知道自己看的是哪一类数据。
2. `/api/bootstrap` 现在返回三态 `source`（`live` / `cache` / `offline`）与 `fetched_at`，判断依据是 provider 与快照内容，**不靠端口**。
3. 坐标轴刻度全部改成整数（价格轴 5/10 步长，蛋白质轴 5/10/15 步长），`niceTicks(maxValue, candidateSteps)` 可复用给下一阶段。

## 一、问题与修复

### 1. 数据来源不可辨识（价格差异的根因）

**现象**：同一组输入，页面显示鳕鱼堡 24.00 / 麦香鸡 17.00，实时接口却是 25.0 / 16.5，看起来像算错价。

**排查**：
- 离线 fixture `data/fixtures/menu_lunch_1215.json` 里 `9900003586 双层深海鳕鱼堡 = 24`、`1450 麦香鸡 = 17`，与用户看到的数值完全一致。
- 实时 `POST /api/refresh` 拉回的菜单里，同两个 SKU 是 25.0 / 16.5。
- 结论：8771/8810 跑的是离线桩，价格来自 fixture，不是算错。

**修复**（不改价格数据）：

| 层 | 改动 |
| --- | --- |
| `src/server.py` | 新增 `Handler._source_kind(info)`，把 provider + 快照归一成 `live` / `cache` / `offline`；`_bootstrap()` 返回 `source` 与 `fetched_at` |
| `web/index.html` | 页头加 `#data-source` 容器（`data-source="live|cache|offline|none"`），下一阶段沿用 |
| `web/app.js` | `renderDataSource()`：实时（绿点）/ 缓存（灰点 + 抓取时间）/ 离线（橙色「离线样例数据，价格不是门店实时价」） |
| `web/style.css` | 徽标点与三态配色（`.src-dot` / `[data-source=…]`） |

`_source_kind` 的判定顺序：provider 是 `offline` → `offline`；快照 `source` 明确写 `live`/`real` → `live`，写 `cache`/`cached` → `cache`；未知值看有没有 `fetched_at`，有则 `cache`，没有才算 `live`。**端口号从头到尾不参与判断。**

### 2. 离线模式报价没有标注

**现象**：离线桩也能「为当前方案报价」，但按钮与实时报价长得一样，用户不知道这是桩数据。

**修复**：`web/app.js` 的报价按钮文案改为 `为当前方案报价`，离线时追加 `（离线桩报价）`（`isOffline()` 读 `BOOT.source`）。

### 3. 「门店与数据说明」信息不全

**现象**：`#meta` 只有一行压缩信息，门店名/代码、日期、餐次时间、来源、营养条目、严格模式挤在一起，未纳入计算的商品直接铺一张表。

**修复**：
- `web/app.js` 新增 `renderMeta()`，逐行列出：**门店名 + 代码**、**日期**、**三个餐次时间**、**数据来源 + 抓取时间**、**营养条目匹配数**（`catalog().rows` / `unique_names` / `aliases` / `duplicates`）、**严格模式说明**。
- `renderUnknown()` 改成 `<details class="unknown-box">`：摘要显示「未纳入计算的商品：N 个（点击查看列表）」，展开才见明细表；0 个时直接写一行说明。

### 4. 坐标轴刻度是小数

**现象**：原 `axisMax` + `fmtTick` 产出 11 / 22 / 33 / 44 / 55 这类刻度，价格轴与蛋白质轴都不可读。

**修复**：`web/app.js` 新增 `niceTicks(maxValue, candidateSteps)`，替代 `axisMax`/`fmtTick`：

- 输入上限 = `max(目标, 最大数据点, 推荐方案) × 1.1`（由调用方先取 max）。
- 步长候选：价格轴 `[5, 10]`，蛋白质轴 `[5, 10, 15]`。
- 输出 `{ max, step, ticks }`：`ticks` 从 0 起严格单调递增、全为整数、`max >= maxValue`、`max % step === 0`。
- 4–6 个刻度是「宜」不是硬约束：能落进 4–6 就选，落不进就取刻度数最少的粗步长（例如 54 → `0,10,20,30,40,50,60`，7 个），硬性三条永远满足。
- 找到 4 刻度的解立即停（最紧凑的合规刻度）。
