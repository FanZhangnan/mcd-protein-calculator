# 09 · 删除全天模式（阶段一）

> 目标：只保留单餐（严格模式），删掉全天三餐规划、已吃记录、剩余目标重排、全天三本账、套餐换配、去酱估算。
> 留底：git tag `v-fullday-final`（commit `12c1d48`）；真实 `data/` 备份在 `data/backup-fullday/`。

## 一、删除前的依赖清单

判定方法：从入口 `/api/*` 与 `web/app.js` 的调用点反查，再看函数被谁引用；凡是只被全天链路引用的，列为删除；单餐链路也调用的，列为保留；只被测试引用而生产代码已无调用的，一并删除。

### 1. 全天独有，删除

#### 接口

| 接口 | 为什么只属于全天 |
| --- | --- |
| `POST /api/plan` | 三餐求解入口，返回 `meals[]` 三张卡 |
| `POST /api/replan` | 依赖 `intake.json` 计算「剩余目标」后重排未吃餐次 |
| `POST /api/intake`、`PATCH/DELETE /api/intake/:id` | 已吃记录（锁定餐次、记账金额、半份） |
| `POST /api/swap` | 套餐换配（round / choice），未接入任何单餐路径 |
| `GET /api/capability` | 去酱能力查询，仅供全天「去酱（估算）」勾选 |
| `POST /api/targets` | 保存全天目标（热量区间/蛋白/脂肪/碳水/日预算） |
| `GET /api/pools` | 全天排查用的可售池转储，单餐不使用 |
| `POST /api/price` | 任意商品试算的调试入口，单餐走 `/api/quote` |

### 2. 共用，保留

| 模块 | 保留原因 |
| --- | --- |
| `src/catalog.py` + `data/aliases.json` | 单餐同样要求 SKU 与营养严格匹配、同名不同规格不合并 |
| `CacheContext` / `ensure_cache` / `_fingerprint` | 缓存按「门店 + 日期 + 餐次时间」隔离，单餐强依赖 |
| `src/quantity.py::purchase_quantity` | 待买数量必须是正整数，报价前独立校验 |
| `plan_signature` / `POST /api/quote` | 409 `stale_signature` / `stale_context` 的报价契约 |
| 基线文件 + `_context_matches` + `POST /api/recompute` | 基线绑定上下文与方案版本，设置变化不得复活旧基线 |
| `removable_options` / `GET /api/removable` | 单餐「点单建议」的唯一数据源 |
| `_detail(code, meal, kind)` | 按餐次时间查特调（514700 早餐有、午餐无） |
| `suggest_remove` | 严格模式下只改点单参数、不扣营养 |
| `400 unsupported_customization` | 未知动作必须报错，`supported` 收窄为 `["suggest_remove"]` |
| `src/mcp_client.py`、`LiveProvider` / `OfflineProvider` | 实时菜单、营养、价格、特调查询 |
| `src/planner.py`：`Targets` / `Item` / `MealPlan` / `sum_nutrition` / `single_meal_rank` / `plan_open` / `single_meal_frontier` | 单餐求解与展示 |

## 二、执行记录

### 删除后保留的接口

```
GET  /                     页面
GET  /app.js /style.css    静态资源
GET  /api/bootstrap        门店/日期/餐次时间、缓存、目录、基线、方案签名
```
