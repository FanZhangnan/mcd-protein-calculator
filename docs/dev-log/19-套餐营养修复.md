# 19 · 套餐营养修复

2026-10-22。分支 `feat/combo-nutrition`，只在本地，未 push、未合并。

## 一、诊断结论（修复前）

19 个套餐 / 31 个变体因营养未知被排除（午餐 17、早餐 2）。逐轮核对 114 个轮次后：

- 未命中的商品 20 个：A 类 0、B 类 7、C 类 3、D 类 10。
- 3 条别名指向营养表里不存在的名称（3755 纯牛奶、521952 龙焰鸡腿堡、507411 麦咖啡™冰美式中杯）；`lookup()` 遇到别名失败就直接返回，不再试名称。全量检查发现同类坏别名共 **13 条**。
- 「堡堡随心拼（7件任选）」的饮品轮 `quantity=2`，`roundList` 只发 1 份，`calculate-price` 返回 60006；同时营养求和只算 1 份，蛋白被低估。
- 另有一个隐藏问题：营养表里同名重复行（如 纯牛奶（盒装）两条）会让括号归一化路径误判为「多个规格」，`纯牛奶(盒装)` 因此变成 `ambiguous_spec`。

## 二、两个 bug

### 1. `lookup()` 别名失败后继续按名称匹配

同时删掉 **15 条**目标不存在的别名：点名的 3 条（3755 纯牛奶、521952 龙焰鸡腿堡、507411 麦咖啡™冰美式中杯），加上全量检查发现的 12 条：

另外修了 `by_norm` 的重复行去重（同名同值的两行不再算两个规格），`纯牛奶(盒装)` 由 `ambiguous_spec` 变为 `official`，`tests/test_catalog.py::test_duplicate_rows_do_not_make_a_normalised_name_ambiguous` 覆盖。

### 2. `roundList` 按轮次数量发送

`src/combos.py` 的 `selection_rounds()` 记录每轮 `quantity`；`round_list()` 用它作为 `comboItemList[].quantity`；`variant_nutrition()` 与 `reference_price()` 也按份数相乘。

影响 6 个可用变体（午餐 5、早餐 1）：
- 堡堡随心拼：3 轮分别是 2 / 3 / 2 份，蛋白从 37 修正为 87（默认）和 89（增肌），`roundList` 发 2 份饮品，试算 73.00 = 参考价。
- 脆香油条豆浆组合：2 根油条 + 1 杯豆浆，蛋白 13 → 18。
- 薄皮V翅双拼十翅、BFF四宫格小食盘：按轮次份数重新求和。

Fixture：`data/fixtures/combo_9900004066_detail.json`；测试 `QuantityRoundTest` 两条（`roundList` 数量 = 2、离线报价 73.00 = 参考价）。

## 四、本轮内替换

`src/combos.py`：`replacement_candidates()` + `apply_replacements()`，在 `build_variants()` 里对每个变体执行。

- 只在**这一轮已有的选项**里换，绝不加套餐没有的商品。
- 饮品：零度可乐 > 纯悦 > 纯牛奶 > 美式 > 其他 <20 kcal 饮品，取第一个可选项。
- 主食 / 小食：先看 `diffPrice ≤ 0`，选蛋白质最高；同蛋白质选脂肪低；再相同按编码。只有加价选项时选加价最少。
- 替换后的变体仍是这个套餐的「默认变体」，每个套餐最多 2 个变体。
- 每个变体都用 `calculate-price` 带 `roundList` 试算，参考价不一致的排除。

实际发生的替换 3 个：

| 套餐 | 轮 | 原选项 → 替换 | 参考价 = 试算 |
|---|---|---|---:|
| 人气经典随心配 | 粉区 | 可乐麦炫酷 → 无糖可口可乐中杯 | 14.90 = 14.90 |
| 精选超值随心配 | 蓝区 / 粉区 | 那么大鸡排（椒盐风味）→ 麦香鸡；怡泉+C麦炫酷 → 无糖可口可乐中杯 | 13.90 = 13.90 |
| 一早现磨 超值二件套 | 早餐主食 | 吉士蛋麦满分 → 大脆鸡扒麦满分 | 14.90 = 14.90 |

结果卡在套餐各轮下方显示「替换 · 粉区：可乐麦炫酷 → 无糖可口可乐中杯（原选项暂无官方营养）」；`items[].combo.replacements` 同步返回，点单时知道要改。

## 九、合并风险

1. **菜单只对 2026-10-23 有效**。套餐目录与快照都是这一天构建的；隔天要重建，否则服务会因日期不一致拒用目录。
2. **苹果片未纳入**：5 个午餐套餐仍因「苹果片一袋(60g)」没有可核对的克数而不可用。如果以后官方表补了规格，把 6102 加进 `combo_nutrition_map.json` 即可，不用改代码。
3. **替换改变点单内容**：人气经典默认是可乐麦炫酷，方案里换成了无糖可口可乐中杯；结果卡和 `combo.replacements` 都写明了，但用户下单时要自己改。
4. **数量轮次影响营养**：脆香油条、堡堡、薄皮V翅、BFF四宫格的营养比旧目录高（旧值漏乘份数），它们的性价比会变化；排行与图表随之变化。
5. **顶部 banner / 社交预览图仍是 50 g / 40.50 的画面**，文字与三张场景截图已更新；品牌图需要重新出图。
6. 会员价套餐（午餐 13、早餐 40）仍未纳入，没有账号上下文。
